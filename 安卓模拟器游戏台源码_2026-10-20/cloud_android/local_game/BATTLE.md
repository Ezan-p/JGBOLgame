# 战斗逆向与本地还原（local-v3）

本轮继续恢复八阵位、阵亡补位和法术释放。代码已经接入本地客户端与实际关卡；当前模拟器存档的 `lineup_capacity` 已由 4 解锁为 8。原四人阵容、角色、装备、资产和通关记录保留，空位由玩家在「阵容 → 布阵」安排。

**证据边界**：原客户端负责播放服务器战报，安装包没有原服务器计算代码。下文区分能从 Lua／CSV 直接确认的行为和本地规则；不能把目前版本称为所有官方战斗系统已经完整还原。

## 八阵位与阵亡补位

`unit/charecter.lua → CChar:AddNextChar` 明确写死双方的对应关系：

| 在场阵位 | 对应后备 | 战场位置（我方 x / 脚底 y） |
|---|---|---|
| 1 | 5 | .10 / .20 |
| 2 | 6 | .35 / .20 |
| 3 | 7 | .23 / .35 |
| 4 | 8 | .22 / .05 |

敌方 x 分别为 .90、.65、.77、.78；原遮挡层分别为 1200、1200、1100、1300。5–8 复用对应前四位的坐标，不是八个人一起挤在场上。

- `fightUI.enterSence` 只让前四位直接入场；后备在入场前不攻击、不受普攻或群攻伤害。
- `CChar.doDead` 先检查服务器是否安排复活；没有复活，播放 `106_1.ccbi` 后调用补位。对应后备不存在时，该位置空缺；不会借用其他位置的后备。
- `doEnterEffect`：延迟 .6 秒，使用 `v2/enterSence.png` 的 4×3 图集前两帧，从斜上方以 .4 秒落场，接 `105_1.ccbi` 爆发及震动。播放器沿用这些资源与时间段。
- 群攻击杀多个前排，战报按阵位依次插入各自的 `enter` 事件；后备从下一轮参与行动。这一行动时机是本地规则，原客户端执行的实际顺序由服务器战报提供。
- 总血槽统计所有参战神仙，包括尚未入场的后备。重放恢复入场前状态；跳过按全部伤害和入场事件恢复最终画面。
- 八阵位存档允许中间空位，用 `0` 占位；移动、休息不会把其他后备挤到错误的对应位置。前排为空而对应后备有人时，本地在开场安排其入场。
- 出战后备与八卦助阵是不同系统；同一神仙仍不能同时占用两者。助阵目标槽为空时清理关联。

该存档只解锁位置，没有额外发放神仙。未解锁的旧存档仍兼容四位规则。

## 法术释放与属性

`csv_config/skill_base.csv` 共 65 项基础技能，`skill_name.csv` 提供名称说明。所有原字段及资源 SHA-256 由 `battle_research.py` 导出至 [battle-mechanics.json](../.runtime/local_game/battle-mechanics.json)。按字段名读取，避免旧脚本位置索引与更新后表结构不一致。

| 字段 | 已确认用途 | 当前实现 |
|---|---|---|
| `use_mode` | 主动 1、被动 2 | 主动参与释放，被动计入属性和入场效果 |
| `effect_target` | 单体 1、群体 2 | 只选择当前在场且存活的目标 |
| `use_probability` | 配置的发动概率 | 每次行动判定，取消固定第三回合 |
| `effect_field` | 攻、守、法力、威力、生命 | 分别读对应数值字段 |
| `intensity / upgrade_plus` | 威力及每级成长 | 读取装备法术实际等级，限制在表中上限 |
| `formula / party_formula` | 服务端公式编号 | 保留编号；没有原表达式，不能声称已恢复 |
| `begin_level / top_level` | 等级范围 | 作为法术配置保留 |

法术槽 1 是原生法术，槽 2、3 是已装备额外法术。两项额外主动都可发动，装备不会覆盖原生法术；两项额外被动也可同时生效。大部分正常单体法术配置概率为 15%，群攻为 10%；内部／引导技能有 0 概率，普通战斗不会人为给它们补概率。演示「龙腾滔天」使用显式开场强制释放，仅用于不写存档的预览。

**多个法术同时存在的仲裁仍是本地规则**：按槽 1→2→3 将配置概率排列成互斥区间，在 `[0,100)` 抽一次；剩余区间普攻。这样每次行动至多放一项法术。原服是否独立抽签、带补偿或按其他顺序仲裁，客户端不足以确认。每个事件保存 `roll / chances / skill_level / spell_position / strength`，战报保存 seed；相同输入及 seed 可重放。正式请求 seed 取关卡与已完成战斗次数，幂等重试返回原战报。

被动属性：原生等级目前为 1，额外法术使用存档等级。攻击、守御、法力和生命的同类百分比相加，再作用于基础属性加装备；随后沿用现有仙缘与助阵计算。这一叠加顺序是本地实现。`battle_stats_ready` 防止进入战斗后重复加成。

原生被动此前漏算，例如孙悟空的「七十二变」现会计入攻击；两个额外槽的被动仍保留。入场播放 `skill_22.lua` 对应的 `127_2 / 128_2 / 130_2.ccbi` 光效和法术名，不把被动伪装成攻击大招。大乘经等非标量技能不套用普通属性公式。

## 本地战报计算

`combat.py` 负责生成战报；`service.py` 负责事务及奖励。以下计算均是本地规则：

- 每轮按我方、敌方和阵位顺序行动；轮初快照决定本轮可行动者，阵亡者跳过，上限 30 轮。
- 普攻伤害：`max(1, round(攻击 − 目标防御 × .45))`，不超过当前生命。
- 主动伤害：`max(1, round(攻击 + 法力 × 法术威力 / 100 − 目标防御 × .45))`。升级增加读取到的法术威力；群攻逐个计算场上目标。不保留旧版凭空的 1.45 强化和 .55 溅射系数。
- 内部治疗技能 6 的播放路径恢复己方在场受伤单位，治疗量为攻击 × .8，上限为最大生命，不复活；原配置概率为 0，须有显式测试／引导事件才使用。无人受伤改为普攻。
- 每条攻击保存 `hits[]`，兼容旧单目标字段；补位是 `kind=enter` 的独立无伤害事件。
- 体力、银两、经验、首通奖励及请求幂等沿用现有事务。暂停、跳过、重放只影响播放，不再次结算。

## 原版战斗链路与扩展系统清单

请求 1026 `msg_fight_request` → 阵容 1028 `msg_fight_lineup` → 战报 1027 `msg_fight_result`。阵容消息含 `first_hand`；基础伤害记录含 `self_use, skill_type, is_src, result, src_order, des_order, damage_count, damage_list[]`。因此动画代码不能反推出原服先手、选目标或暴击计算。

播放链：`showFightDetailStepByStep → showSingleAttackEffect_private → skill_mgr.showSkill → skill_<id> → CChar.beAttack → 下一步`。补充事件由 `showFightEvents` 按 `cur_action` 调度，`logic_type > 100000` 转交 `skillExt.showSkillExt`。复活先登记在 `g_fight_events_revive`，死亡处理据此跳过补位；不能简单把复活等同负伤害。

| 逆向部分 | 已提取证据 | 当前恢复范围／缺口 |
|---|---|---|
| 基础主动法术 | 65 项技能定义、33 组专属施法／命中特效映射 | 原生＋装备释放、概率、成长、单体／群体、原画特效已接入 |
| 被动属性 | 技能表、`skill_22`、`lastBuffList` | 标量属性及入场展示已接入 |
| 扩展特技 | `ext_skill` 38 项、`skill_ext_base` 38 项、名称 38 项 | 参数与事件路由已完整导出；尚未接入特技装备及触发引擎 |
| 大乘经 | `rulai_skill_base` 10 级吸收／护盾概率 | 缺护盾量、分摊结算和优先级，未猜测启用 |
| 法术觉醒 | `awaken_skill_conf` 3 项，`awaken_skill_rate` 54 项 | 原材料、加成、概率表已导出；当前存档无觉醒装备流程 |
| 法术进阶 | `skill_advaced_conf` 8 项，`skill_value` 10 行 | 配置已导出；未冒充当前已具备的能力 |
| 助阵法术成长 | `cheer_skill_config` 501 行 | 保留完整原表，当前仍沿用已实现的八卦助阵系统 |
| 剧情分步入场 | `enterSenceByStep`、角色 `step` | 已定位，当前十个本地关卡未接原剧情事件脚本 |

## 战斗画面与操作

沿用上一版已恢复的原生背景、四点站位、姓名血条、顶部总血量、左右镜像与遮挡。人物按原 `.57 × 屏高 / 512` 缩放。普攻为残影、突进、方向刀光、受击变色／震动、飘字及返回；大招为暗幕、放大立绘、墨迹速度线、原书法技能名、施法和命中特效。104「龙腾滔天」播放三波水龙，数值只结算一次。时间轴重新编排，未宣称逐帧等同原服。

- 「阵容 → 布阵」拖动到已有或空阵位；点空位选择神仙。后备 5–8 分别对应主位 1–4。
- 「旅途 → 已开放关卡 → 开战」播放实际战报。
- 「阵容 → 战斗演示」查看截图风格；演示内可切到「龙腾滔天」。
- 暂停／继续、音效、跳过、重放与安卓返回仍可用。

## 构建与验证

```sh
.runtime/venv/bin/python scripts/build_local_game.py
.runtime/venv/bin/python -m unittest discover -s tests -p 'test_*.py'
.runtime/venv/bin/python manage.py install
```

Python 服务修改后需重启项目拥有的本地游戏进程。构建同时生成基础 catalog、battle 资源数据及 `battle-mechanics.json`，对资源来源和哈希进行记录。

本轮验证文件位于 `.runtime/local_game/battle-v3-validation/`；存档备份 `before-unlock.sqlite3`，精确变更记录 `unlock.json`。自动测试覆盖后备不被提前命中、群体阵亡四人补位、双装备法术、升级伤害、零概率技能、固定 seed、空主位后备、八位交换／移除、被动不重复计入以及原有持久化事务。

上一版画面与 76 组主动法术加载记录仍保留于 `battle-validation/`，不能将旧版 46 项测试当作本轮验证结果。

本轮验收：**73 项测试通过**。原引擎隔离战报包含 16 名神仙、28 个事件和双方共 8 次补位；完整播放、跳过、重放、暂停均通过，当前测试进程没有 Lua 错误。正式存档已实机确认八格无锁，第八空位可进入神仙选择列表。资产核对无变化；正常登录仅更新保存／体力计时字段。详见 [validation.json](../.runtime/local_game/battle-v3-validation/validation.json)。
