# 旅途关卡逆向、实现与推测说明

更新：2026-10-23。用户已授权在没有原服务端和抓包的情况下，根据客户端线索推测，并明确标注。

## 当前实现

已将 **67 章、597 个小关**接入原生旅途界面、战斗、存档、背包与结算。配置数值直接读取 APK 1061 及项目保存的 1263 更新资源，没有按关卡编号生成数值，也没有削弱后期敌人。普通关 463 个、精英关 67 个、首领关 67 个。

**原始配置完整，不等于服务端算法已完整还原。** 概率抽样、经验分配、部分首通语义、战斗伤害仍含推测。所有结算返回 `settlement_status=client_config_inferred_rules_v1`、规则版本和抽样记录；结算页也有标注。

完整逐关数据：[全部关卡与推测规则.json](../outputs/journey-20261023/全部关卡与推测规则.json)。包含全部原始行、敌方阵位和属性、奖励、首通、99 级行者经验表、资源来源 SHA-256 及推测规则清单。可运行 `python scripts/export_journey.py` 重建。

## 客户端可确认的规则与证据

- `csv_config/newbie_content1.csv` 第 15–16 项：旅途大胜（三星）评价依据双方总血量上的星标。
- 反编译 `lua/ui/fightUI.lua:1418` 的 `showAllHp`：剩余总血量比例低于 **0.7** 熄灭第三颗星，低于 **0.4** 熄灭第二颗星；等于阈值仍亮。正式 `pass_star/final_result` 由服务器返回，本地用此客户端线索重建评价。
- `csv_config/newbie_content3.csv` 第 16 项：**首次三星**通过小关可获得双倍经验与银币。不是“任意首次胜利翻倍”。全三星完成大关有额外奖励。
- `lua/ui/subLevelUI.lua` 的 `parseRandomPrize` 只读取奖励前四项，未提供 rate 抽样算法；三星已领取显示取决于 `pass_star==3`。
- `lua/ui/mainUI.lua` 的 `getRefreshTime/updateRefreshTime/beginRefresh` 与 `lua/ui/mapUI.lua:freshMapData`：午夜重置日挑战计数。
- `lua/ui/fightUI.lua:2211` 读取服务器 `rewards.role_exp`；2825 附近逐位读取 `rewards.cor_exp[]`。它们是不同奖励。
- `role_level_config.csv` 提供升级门槛与胜负经验；`cortege_experience.csv` 提供每个品质、等级的神仙升级需求。经验书的效率分段来自原版 `expbookUI.lua`。

上述行号是本项目 `.runtime/research/lua/` 反编译副本的位置。导出 JSON 记录原资源摘要，避免把文字说明当作唯一依据。

## 推测规则（不是原版服务端代码）

集中实现在 `journey_rules.py`，版本 **journey-inferred-v1**；数值输入始终取原表。

| 规则 | 当前推测实现 | 依据与不确定点 |
|---|---|---|
| 普通掉落 | 每项独立抽整数 1–100，`roll <= rate` 命中；允许同时掉多项；0 永不命中、100 必中 | rate 的 0/10/15/20/30/100 取值支持百分比解释，但服务端也可能按权重择一或有保底 |
| 专用首通掉落 | 首次胜利且首通表非空时，使用首通表替代普通掉落表 | 字段命名支持“首通表”，替代而非叠加仍是推测；普通表和首通表都保留 |
| 首通经验 | 仅首次胜利抽 `first_win_prize.rate`；命中后每位出战神仙增加 `exp_count` | 字段头给出数量与 rate，但触发时机、发给谁仍需推测 |
| 经验计算顺序 | `基础 exp × 首次三星倍率 + 首通额外经验` | 首次三星基础翻倍有文本依据；额外经验是否也翻倍未知 |
| 神仙经验分配 | 每位已部署神仙获得上述经验，不按人数平分，含阵亡及替补；失败和平局不给神仙经验 | 原界面按每位神仙显示经验，但服务端分配式不可见 |
| 神仙经验效率 | 复用经验书规则：低于 floor(行者等级×2.5) 全额；到等级×3 前 20%；等级×3 封顶，品质表最高 600 | 经验书规则可确认，将它用于战斗经验是推测。先发修为再计算神仙上限，允许行者本次升级立即提高上限 |
| 行者修为 | 按战前等级查 `win_exp/lose_exp`；平局按失败；不因首次三星翻倍 | 字段语义支持胜负修为；不把 `cortege_exp` 再叠加，避免重复计算，真实组合未知 |
| 三星评价 | 胜利且剩余总 HP ≥70% 为 3 星，≥40% 为 2 星，其余胜利 1 星；失败／平局 0 星 | 客户端星标阈值确定；取本地战报最终总 HP，含替补和变化后的最大 HP，是对服务端评价的推测 |
| 消耗与日计数 | 每场已完成战斗扣 1 体力并加一次日计数，失败／平局不返还 | 客户端不能确认失败返还机制；当前明确按挑战次数处理 |
| 午夜时区 | 亚洲／上海 00:00 重置 | 午夜有客户端依据；旧服实际时区未核实 |

三星奖励每关只发一次；全章三星奖励每章只发一次。最高历史星数不会被后续低星覆盖。首次胜利拿到 1–2 星后，再取得 3 星仍可获得首次三星翻倍和奖励。

抽样随机流独立于战斗随机流，种子与规则版本、关卡 ID、战斗序号关联。结算返回 `random_audit`，可复现每个 rate、roll 和 hit。此设计用于本地可审计性，不代表原服随机数实现。

战斗伤害、先手和部分技能机制继续使用现有本地战斗引擎，参见 [BATTLE.md](BATTLE.md)。因此，尽管敌方表值未改，本地胜负和过关难度不保证与原服一致。VIP 次数加成、活动加成、付费重置、扫荡、`genius_prob` 对应的随机玩法未在本次新增。

## 存档与一致性

- 本地 ID 扩展为 1–597，原版 ID 单独保留；旧的 1–10 仍对应 101–105、201–205，没有重新解释存档。
- 旧银两、角色、阵容、背包、胜场和解锁进度保留。旧存档的显示星数优先按历史战报最高评价恢复；没有战报仅按已胜利确认 1 星。恢复显示不改变奖励领取资格。历史本地首通翻倍收益不追扣。
- 行者升级不再使用固定每 200 修为一级，改用原版 99 级门槛。旧修为迁移时保留原等级及进度比例，并保存旧值与转换值；旧等级高于原表上限时限于 99 级。迁移不是原版规则，是兼容本地旧档的处理。
- 每次请求在 SQLite 单事务中扣体力、计数、更新星数、发奖和存储战报。相同请求 ID 重试返回原战报，不再次抽奖、扣体力或发奖；失败校验回滚整个请求。
- 完整不可变配置打包为 Lua 表，运行状态只传 597 关的简要进度，避免在每次背包操作中重复传输完整阵容与奖励资料。

## 文件与复现

- `journey.py`：无损提取关卡与原素材信息。
- `assets.py / battle_modes.py`：接入全部关卡及敌方阵容，缺失敌人或素材直接报错，不静默替换。
- `journey_rules.py`：可替换的推测抽样和首通经验规则。
- `journey_runtime.py`：进度、每日次数、星数、背包与货币结算。
- `role_progression.py`：原版行者等级表与旧存档迁移。
- `tests/test_journey_runtime.py`：全部 597 行原表与阵容核对、全部关卡路由、阈值边界、首通与首次三星区分、跨日、重试、原子回滚、推测概率端点和存档迁移。

```sh
python scripts/export_journey.py
python -m unittest discover -s tests -v
python scripts/build_local_game.py
```

自动化测试验证实现与所声明规则一致，不能证明推测算法等同于原服。后续若得到服务端或抓包，优先替换 `journey_rules.py` 中的抽样与经验语义，再对照已记录的抽样审计与逐关原值。

## 原版星级与开战布局还原

原版 `subLevelUI.lua:createSubLevel` 使用 `v2/introUI/stars.png` 五星横条，按 `pass_star/5` 裁剪，仅绘制已获得星数，没有空心星。星条中心位于人物中心下方 0.05 屏高，缩放为 `g_scaleW*2`（960 逻辑宽度对应 1.5 倍）。本地卡片对应中心 `(x,90)`，即全局 y=190，星条高度 33，与参考图人物腰部的金星一致。选中框改用原版 `choose_up/choose_mid` 素材，开战图片按原比例显示并位于星条上层。

原版 `subLevelUI.startFight -> mapUI.fightNpc` 校验进度、体力、等级及次数后直接发送战斗请求，没有本地新增的棕色确认框。因此已删除该确认步骤，点击开战直接进入战斗；奖励详情弹窗不受影响。

旧星级从 SQLite 请求历史中的明确星数、最终 HP 或早期逐击 HP 战报恢复，并取最高记录；只有胜场而没有战报的关卡显示 1 星下界，不虚构三星。恢复结果保存在 `legacy_stars`，只用于显示，不重新发奖、不扣体力、不改变首次三星奖励领取记录。迁移只执行一次。

本次星级／开战调整通过 15 项旅途测试与 9 项服务回归测试，并在原玩家存档中确认 11 个已通关小关恢复显示星级。实机截图：[原版星级位置](../outputs/journey-20261023/原版星级位置实机.png)。
