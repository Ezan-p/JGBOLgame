# 浏览器 MOD 测试器

> 原 Noctilucent 项目的历史文档，不适用于《金箍棒》。此测试器未在金箍棒游戏台中开放；当前使用方式请阅读 [README.md](README.md)。

五条悟素材包已接入：打开 **http://127.0.0.1:8765/mod/?preset=gojo** 即可载入角色、播放动画与合成样音。参见 [v0.2交付说明](../character_mods/gojo_satoru/实际素材与测试器交付_v0.2.md)。

准备制作完整新角色时，先阅读 [新角色制作要求与素材清单](../新角色制作要求与素材清单.md)，其中包含好感度、剧情演出、立绘、Spine/3D、技能、语音及原游戏接入的交付要求。

入口：**http://127.0.0.1:8765/mod/**。也可以从游戏台顶部的「打开角色 MOD 测试器」进入。启动方式沿用 `启动游戏台.command` 或 `python3 cloud_android/manage.py start`。

这是基于当前目录实际提取数据的本地配置沙盒，可用于新增角色设计、数值对比、技能参数检查、独立测试卡池抽样以及功能验收记录。页面不连接安卓控制通道，不修改原始游戏文件或存档。网页服务运行时，测试器的配置操作不需要安卓游戏登录。

## 从新角色开始

1. 首次打开会从伊凡 1001 建立新角色草稿：角色 ID `900001`、PVE 技能 `990001`、PVP 技能 `990002`。新建会要求确认替换当前编辑内容。
2. 编辑名称、基础 HP/ATK、等级等。修改角色 ID 会同步角色配置内命名为 `pet_id` 的旧角色引用，以及独立测试卡池内的旧 ID。其他独立 ID 空间不会被盲目替换。
3. 在完整 JSON 编辑器里修改更多字段，点击「应用 JSON」。未应用的编辑也会在保存、检查、试算和导出前解析；语法错误会阻止操作并保留输入。
4. 点击「运行检查与差异比较」。新增模式检测原角色/技能 ID 冲突；覆盖模式允许复用原技能 ID，但需要角色已存在。
5. 执行技能试算和抽卡测试。更改草稿会清空旧的测试结果，避免把旧结果误认为新配置的结果。
6. 「保存到本浏览器」写入当前站点的 localStorage；重新打开后点击「恢复已保存草稿」。没有自动保存，也不会静默覆盖现有保存。`localhost` 与 `127.0.0.1` 的浏览器存储互不相通。
7. 导出 `mod-draft.json` 用作长期备份或共享。导入上限 2 MB，仅支持测试器草稿格式，不直接接受官方配置表或 APK。
8. 导出 `MOD-测试报告.md`，包含来源摘要、配置错误/提醒、相对初始克隆模板的差异、最近一次试算及抽样参数、功能检查项、完整草稿。

默认草稿保留伊凡的头像、技能图标、成长材料、职业、增补条目及剧情等关联数据，用于原型验证，不等于独立原创角色的完整注册。原角色组成员关系已清空；剧情、对话等表自身的记录 ID 仍是模板值，真正回写前需要单独处理。页面顶端头像固定展示模板，不是 Unity 模型/动画预览器。

## 编辑技能

草稿中的关联路径：

```text
character.pet_active_skill.skill_id → skills["990001"]
character.pet_active_skill.pvp_skill_id → skills["990002"]
```

每项技能保留 `base` 和 `levels` 原字段。修改 ID 时需要同步表键、`base.id`、`levels.skill_id`、各级 `id`，并自行处理 `pair_up_ids` / `property[].pair_up_id`。新建克隆时会自动同步模板自身的这些技能引用。修改冷却需同时修改 `base.cd[等级-1]` 与 `levels[等级].cd`。

示例：把新角色 PVE 一级伤害倍率从 3 改为 4，修改：

```text
skills["990001"].levels["1"].property[0].affects[0].affect_values[0] = "4"
```

攻击力输入 452 时，沙盒伤害由 1356 变为 1808。基础表描述、等级描述等文本也应自行同步；测试器不会自动重写中文描述。修改 PVE 不会自动修改 PVP。

当前数值模型仅针对模板的 `skill_type_id=1`（伤害）和 `73`（吸血参数）：

- 伤害 = 输入攻击力 × type=1 的第一个参数。
- 假设吸血 = min(上述伤害 × 吸血百分比 / 100，单次上限)。只作参数演示，不代表施放本技能会立刻回血。
- 持续回合与 CD 仅展示，不执行回合状态机。
- 未实现防御、暴击、属性、目标选择、Buff 叠加、被动、AI、成长公式或真实回合结算。
- 出现未知效果会报告提醒，并拒绝数值试算；不会把未知机制当成已支持。

技能参数数组、CD 一致性、缺失等级、绑定技能、内部主 ID 会检查；所有字段的官方 schema 尚未还原，检查通过不代表原游戏可以加载。

## 资源与卡池

资源检查范围是提取的角色 1001 的 455 个候选地址，可展开查看内部 ID、Bundle 依赖及来源文件 SHA256。没有匹配只表示不在这份子索引内，不代表整个 APK 中不存在。新增的模型/贴图尚不能直接在此导入、渲染或注册到 Unity Addressables。

测试卡池使用**相对权重**，默认伊凡 99、新角色 1，即独立测试模型中的 99%/1%。最多抽取 100000 次，种子为 uint32；使用固定 LCG PRNG，相同种子、次数、行顺序与权重可复现。零权重不会被抽中；重复角色、未知角色、负数/无效权重会阻止测试。

此处没有保底、活动、分组或服务端抽奖逻辑。原包的三条候选卡池证据仅供查看，`rate=100`、`prob=0.08/0.2` 不会直接当作实际概率使用。抽样不会发放真实角色。

## 新功能测试与真实游戏验收

在「功能验收记录」中新增功能名称、测试步骤及结果，手工选择「未测试 / 通过 / 失败」。这些是测试者的记录，不是自动执行新增任意游戏代码。建议覆盖显示、获得、上阵、技能、结算、存档恢复。

要在原游戏执行新增角色，仍需完成 protobuf schema、运行时配置优先级、资源注册、回写重加密和 APK 安装验证。测试器没有提供尚未验证的「一键注入」。之后建立回写链路时，可将这里导出的草稿作为输入，但必须编写并验证转换器，不能直接把草稿 JSON 替换官方配置。

## 实现与验证

- `web/mod/core.mjs`：克隆、校验、差异、技能算术和确定性抽样，可独立测试。
- `web/mod/app.mjs`、`index.html`、`style.css`：浏览器 UI；用户输入以纯文本显示。
- `web/mod/seed.json`、`icon.png`：从现有提取结果生成的静态快照。
- `scripts/build_mod_seed.py`：重新生成快照，来源为 `mod_analysis/character_1001` 及完整角色/技能表；不改 APK。
- `tests/test_mod.mjs`：10 项核心逻辑测试。
- `scripts/check_mod_browser.py`：在隔离 Chrome 会话中检查编辑、保存/恢复、试算、可重复抽样、导入/导出、ID 冲突、JSON 错误保留、功能项、报告下载和移动布局，不操作安卓。

```sh
node --test cloud_android/tests/test_mod.mjs
cloud_android/.runtime/venv/bin/python cloud_android/scripts/check_mod_browser.py
```

验证记录与截图位于 `.runtime/mod-browser-check.json`、`.runtime/mod-browser.png`、`.runtime/mod-mobile.png`。原游戏台的回归测试使用 `tests/test_gateway.py`。
