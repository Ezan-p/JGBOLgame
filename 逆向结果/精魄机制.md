## 对象、品质、持有与列表

精魄的物品主类型是15（`ext_skill`），物品对象类型是5。基础金色精魄为10101—10119，品质字段为4；高级紫色精魄为10201—10219，品质字段为5。两组各19种，不能将“金色”误写为比紫色更高级。

实例需要保留：唯一ID、类型、等级、所属神仙、精魄位置与升级补偿进度。原字段包括 `id/type_id/level/owner_id/ext_skill_pos/prob_compen`。列表按已铭刻优先、品质降序、等级降序、类型ID升序排列。新本地界面按实际持有实例展示，保留同类型多个实例；图鉴继续显示38项资料。

精魄不是魂魄，不使用神仙幻魂规则；精魄石10000是升级材料，不是可直接兑换银两的货币。紫色碎片10001与扭转丹1342也不是精魄技能实例。

## 铭刻与格子

行者38级开启。客户端正常显示四个基础精魄位；是否开启由神仙数据 `equiped_ext_skill_limit` 决定，不可据此初始化为四格全开。更新资源还存在五法界魂/相关成长体系开启第五位的说明；本轮没有恢复该体系的完整服务端判定，不能把四格上限推广为所有版本的绝对上限。

原提示 `jpmk_tink1`：每次铭刻随机覆盖已装备精魄，或开启新格；紫色优先覆盖同类型金色；开格失败增加幸运值，幸运值越高，下格开启概率越高。

原提示 `jpmk_tink2`：铭刻随机开启或神仙飞升指定次数自动开启。界面使用 `i * 6 - 6` 生成次数，另有格子使用仅随机开启的 `jpmk_tink3`。这不能推出开格概率或幸运值递增数值。

不可铭刻同品质同类型精魄。已铭刻精魄没有在该客户端流程中提供自由卸下、跨神仙搬运按钮。选择页只接受 `owner_id == 0` 的实例。请求：

```text
msg_equip_ext_skill
  ext_skill_id: 精魄实例ID
  des_cortege_id: 目标神仙实例ID
  lock_list: 本次锁定的实例ID列表（序列化）
```

紫色精魄可临时锁定，锁定后本次不被覆盖，至多锁定3个（`MAX_JP - 1`）。配置虽然有4个锁定价格档，不能由此推断此页面允许锁4个。价格表是锁定数量对应值，不是逐项相加；具体余额扣除与结果仍由服务器返回。

**缺失：** 初始格数发放、开格抽样、幸运值增量及上限、覆盖候选抽样、等级与进度继承、铭刻消耗/回收的完整结算。已取消本地“自由装卸四个精魄”的替代入口；不删除旧存档中已经装备的实例。

## 升级

5级上限。当前1/2/3/4级对应进度门槛为500/1000/1500/3000。界面显示：

```text
进度百分比 = floor(prob_compen / 门槛 × 100)
本次请求精魄石数 = min(500, 持有精魄石数, 门槛 - prob_compen)
msg_upgrade_ext_skill {ext_skill_id, cost_count}
```

材料为10000精魄石；当前资源只要求持有数量大于0。字符串表中遗留“至少50颗”的提示不能覆盖当前 `pressUpdateJP` 的实际逻辑。

**进度百分比不能直接认定为成功概率。** 客户端只提交请求并处理返回，未包含每颗石头的成功概率、失败进度增量、提前成功、成功后剩余材料/进度处理公式。不能把500/1000/1500/3000写成已证实的固定升级总价，也不能以银两直接升级。

本地返回原始进度、门槛与单次上限；尚不扣石头或模拟未知升级结果。

## 分解、碎片合成与转换

`material_transform` 102组：每个1级101xx精魄 + 1000银两 → 20精魄石。

103组：每个1级102xx精魄 + 1000银两 → 100精魄石。

选择逻辑排除已铭刻实例。本地实现这两种已核实配方；2级以上或已有升级进度的返还/继承规则不明确，拒绝消耗。配方直接读取原表。

7组：20个紫色精魄碎片 + 500000银两，随机合成紫色精魄。原表候选中10204出现两次且权重不同，10203缺席；不能擅自修表或宣称19种等概率。保留原始配方，本轮不生成随机奖励。

`jingpo_transform`：38级，1个1级紫色精魄 + 1颗1342精魄扭转丹。转换组：

| 组 | 类型ID |
|---|---|
| 高级连击、高级强袭、高级战意 | 10207 / 10211 / 10212 |
| 高级斩杀、高级破甲 | 10215 / 10202 |
| 高级破法、高级咒罚 | 10209 / 10216 |
| 高级威慑、高级祝福 | 10201 / 10218 |
| 高级强壮、高级幸运 | 10213 / 10214 |
| 高级格挡、高级愈合 | 10206 / 10210 |
| 高级反击、高级法抗、高级招架 | 10203 / 10208 / 10204 |
| 高级复活、高级清心、高级嗜血 | 10219 / 10217 / 10205 |

名称以逐级参数表中的原始配置名为准。每个来源排除自身，目标字段权重为0且 `is_random=1`。只有一个目标的5组（10条方向）可无随机歧义地接入；有两个目标的转换不能据0推断均匀概率。仅处理1级、无进度、未铭刻实例；不会让玩家指定原本随机的目标。

## 技能与战斗边界

完整参数见[精魄逐级参数](../安卓模拟器游戏台源码_2026-10-20/cloud_android/outputs/essence-20261023/精魄逐级参数.md)，共190条，不用基础等级描述代替高级效果。

19族包括攻击削弱、防御削弱、反击、招架、吸血、格挡、连击、法抗、穿透、回合恢复、额外伤害、周期加攻、生命上限、恢复增强/斩杀闪避、追击、中毒、净化、祝福与复活。例：高级咒罚5级中毒参数12.5%，原描述注明持续3回合、可叠加、单次最多20万；紫色复活每场最多2次，基础金色最多1次。

现有 `combat.py` 已读取这38项精魄的逐级参数和已装备实例，因此本轮保留旧存档效果及原战斗测试。该战斗引擎仍包含已标注的本地伤害/触发策略，不据原CSV数值就宣布战斗完全等同官服。未伪造150xxx新增特殊技能的取得与铭刻体系。

## 猎魂与取得来源

物品说明指向猎魂之地；已导出 `hunt_ball_config`、`hunt_soul_config`、每日/每周奖励配置。球类型1/2/3的配置为20/40/60精力、1/3/5碰撞次数；魂类型1—5价值为20/40/60/100/200，原表另有基础数量、随机数量与权重。

这些字段本身不能推出完整地图生成、碰撞、随机发奖与账户精力结算。本轮没有给玩家发放虚构的初始精魄，没有保留银两直接购买精魄的捷径；因此空存档的精魄列表可以为空。猎魂来源仍是完整可玩闭环的缺口。
