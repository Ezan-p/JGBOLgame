# 装备升阶阶数标记与循环特效

2026-10-23，补充[装备升阶系统](装备升阶系统.md)。参考图为 `素材图/IMG_3412.JPG`、`IMG_3438.JPG`。本次只补显示，不改变升阶费用、属性或存档进度。

## 原版结论

阶数标记使用 `v2/equipAdvanceUI/ad1.png`～`ad10.png`，每张35×35像素，紫色方底及金色汉字“一”至“十”，不是普通字体。零阶无标记。图标原有品质边框来自物品图集，升阶并不替换装备品质。

不同页面使用不同位置：

- **阵容已装备槽位**：原 `charPositionUI.createCharInfo` 对应分支把标记作为装备图标的子节点，锚点 `(1,0)`，位置为图标宽高的 `(0.93,0.07)`，即右下角。左上角强化等级是白色Arial字号22，锚点 `(0,0.5)`，位置 `(0.1,0.8)`；等级与阶数独立。
- **包裹列表**：原 `common/createCell._createCell` 把标记放在**名称右侧**，先测量名称宽度，再把图片放到文字末端，图片锚点 `(-0.1,0.5)`。截图中“筋斗云 六”“风火轮 十”对应这个规则；列表图标并不另外重复叠加右下角阶数。
- **装备详情**：`packageUI.createItemIntroLayer` 同样在名称末尾使用原阶数图片。
- **升阶装备选择器**：调用 `createCellWithOwnerNoBtn`，沿用列表名称旁标记和图标特效。

## 原版四档特效

`data.getCcbiByAdvanceLevel()` 明确给出映射，以下不是按截图猜测的阈值：

| 装备阶数 | 原版动画 | 锚点 | 显示效果 |
|---|---|---|---|
| 零阶 | 无 | — | 品质图标，无阶数牌 |
| 一、二阶 | 无 | — | 品质图标及阶数牌 |
| 三、四、五阶 | `01.ccbi` | `(0.5,0.56)` | 金色闪点、流光 |
| 六、七、八阶 | `02.ccbi` | `(0.5,0.45)` | 橙红色流动火焰 |
| 九阶 | `03.ccbi` | `(0.5,0.56)` | 火焰与金色线框 |
| 十阶及以上分支 | `04.ccbi` | `(0.5,0.56)` | 红橙火焰与红色线框 |

当前升阶系统最高十阶。原函数的 `>=10` 是客户端显示分支，不表示有已恢复的十一阶玩法。

每套CCBI引用同名目录内的原图集，例如 `04/04.plist` 与 `04/04.png`。保留原CCBI中的透明度、逐帧切换、混合方式与循环时间，不用静态火焰覆盖图或自行拟合闪烁。注灵/升阶完成的 `shengjie.ccbi`、`shengjie02.ccbi` 属于一次性成功演出，与本次常驻图标特效不是同一套资源。

`data.addAdvanceCcbi()` 的原实现将动画附加在图标内：

```text
动画位置 = (图标宽/2 - 原生视口宽/2, 图标高/2 - 原生视口高/2)
动画缩放 = 图标原始宽 / 120
动画锚点 = 上表对应锚点
```

本项目原物品图格为100×100，因此图标内部动画缩放为5/6。外层图标再随包裹74像素、阵容78像素等尺寸缩放。包裹原 `createCell` 使用0.8333333333333334，等价于该100像素图格的规则。保留原生CCLayer的锚点行为，不以本地960×540逻辑画布替换原生视口，否则动画会偏移。

## 实现

新增共用 `local_game/equip_visuals.lua`，接入：

1. 包裹装备列表：名称后阶数牌、图标循环特效。
2. 阵容三个装备槽：白色强化等级、右下角阶数牌、图标循环特效。
3. 装备详情：名称后阶数牌。
4. 升阶装备选择器及阵容更换装备列表：阶数牌和循环特效。

标记以真实装备实例的 `advance_level` 为准，不从名称、品质或强化等级推断。法术、灵石、神仙头像不套用装备升阶特效。动画随图标销毁与滚动视口裁剪，关闭再打开不会累积图层。原版装备详情大图没有此常驻特效调用，因此不额外向详情大图、强化弹窗或升阶主面板添加火焰。

源码中还有优先显示 `cast_level` 铸造标记，以及 `star_level==1` 六星装备边框的分支；它们属于铸造、装备升星系统，不应把这两张图中的升阶标记误认成那些机制。本地现有升阶装备使用 `adN`；本次没有新增铸造或六星装备玩法。
