# 原版“成长潜力”增加渠道逆向结论

先给结论：

- **详情页四条“成长潜力”数值本身，原版客户端没有任何玩家可操作的提升渠道。**
- 这四项是英雄模板的**先天成长系数**，来自 `cortege_base_0.csv`，客户端只读取、只用于详情页条形比例，不会因升级、培养、飞升、转生、传承、装备或仙缘而改写。
- 玩家实际能提升的是三类相邻概念：
  1. **潜能点 `culture_point`**：用于培养的“货币”。
  2. **培养值 `hp_plus / gongji_plus / fangyu_plus / magic_plus`**：培养直接增加，飞升/转生后再叠加。
  3. **当前四维属性**：等级、飞升、转生、仙脉、装备、法术、仙缘、助阵共同计算。

---

## 一、为什么说四条“成长潜力”不会增加

### 1. 数据来源固定

`cortege_base_0.csv` 第 11～14 列：

| 列 | 字段 | 含义 |
|---|---|---|
| 11 | `base_gongji_plus` | 攻击成长 |
| 12 | `base_fangyu_plus` | 防御成长 |
| 13 | `base_maxhp_plus` | 生命成长 |
| 14 | `base_maxmagic_plus` | 法力成长 |

`ui/lineupUI.lua:495-521` 只做解析：

```lua
character_attr.damageOffset  = tonumber(v[11])
character_attr.defenceOffset = tonumber(v[12])
character_attr.hpOffset      = tonumber(v[13])
character_attr.manaOffset    = tonumber(v[14])
```

并计算全角色最大值 `g_characterMaxGrowth`，用于详情页条形归一。

### 2. 详情页只读

`ui/formationUI.lua:1026-1041`：

```lua
if argInfoTab.csvInfo and argInfoTab.csvInfo.manaOffset then
    tmp_user_pro.mp  = argInfoTab.csvInfo.manaOffset
    tmp_user_pro.hp  = argInfoTab.csvInfo.hpOffset
    tmp_user_pro.ad  = argInfoTab.csvInfo.damageOffset
    tmp_user_pro.def = argInfoTab.csvInfo.defenceOffset
end
tmp_user_pro.mp_rate  = tmp_user_pro.mp  / g_characterMaxGrowth.mana
tmp_user_pro.hp_rate  = tmp_user_pro.hp  / g_characterMaxGrowth.health
tmp_user_pro.ad_rate  = tmp_user_pro.ad  / g_characterMaxGrowth.damage
tmp_user_pro.def_rate = tmp_user_pro.def / g_characterMaxGrowth.defence
```

这里没有任何写回逻辑，也没有 `hpOffset = ...` 之类的玩家成长写操作。全量搜索确认：`*Offset` 只在 `lineupUI.lua` 从 CSV 赋值，没有其他地方修改。

因此，**原版玩家无法把这四条成长值练高**；换英雄模板才会看到不同数值。

## 二、玩家实际可提升的成长相关系统

### 1. 培养（训练）——提升培养值，不提升先天成长

相关文件：

- `ui/trainingUI.lua`
- `common/common_def.lua`
- 协议：`msg_cortege_train_request = 1081`、`msg_cortege_train_confirm = 1082`

原版培养会增加：

- `hp_plus`
- `gongji_plus`
- `fangyu_plus`
- `magic_plus`

`trainingUI.lua:1021-1099` 明确显示：

```lua
local appendAttri = "(" .. g_characterInfo.hp_plus + point .. ")"
local str2 = tostring(g_characterInfo.hp + point) .. appendAttri
```

即培养点直接加到当前属性和 `*_plus` 上。

培养消耗：

- **蟠桃 1001**：单次至少 5 个；十连至少 50 个。
- **精心培养**：额外消耗元宝，单次 1 元宝、十连 10 元宝。
- **潜能点 `culture_point`**：可直接作为消耗来源。
- 也可能消耗另一项已培养属性，形成“此消彼长”的重新分配。

`trainingUI.lua:930-949`：

```lua
[culture_max_hp_plus]      = 0,
[culture_wuligongji_plus]  = 0,
[culture_wulifangyu_plus]  = 0,
[culture_max_magic_plus]   = 0,
[data_table.increase_field] = data_table.train_point
```

培养结果界面会以绿色 `+N` 或红色 `-N` 显示，并有保护字段：

- `train_max_hp_protect`
- `train_max_magic_protect`
- `train_wuligongji_protect`
- `train_wulifangyu_protect`
- `train_adjuct_rate`

这些是服务端随机/保护参数，客户端只显示结果。

> 结论：培养提升的是“培养值”和当前属性，不会改变详情页四条先天成长潜力。

### 2. 潜能点来源

潜能点字段：

- `culture_point`：当前剩余潜能点
- `level_culture_point = 83`：升级相关潜能点
- `evolve_culture_point = 84`：飞升相关潜能点
- `total_culture_point = 85`：累计潜能点

来源包括：

#### 升级

- 角色升级时由服务端下发 `level_culture_point`。
- 客户端没有升级潜能点表，具体每级数值由服务端计算。
- 升级本身还会按“基础属性 + 基础成长 × (等级−1)”提高当前属性：

`inheritUI.lua:1133-1141`：

```lua
health = csvInfo.hp + csvInfo.hpOffset * (level - 1)
damage = csvInfo.damage + csvInfo.damageOffset * (level - 1)
defence = csvInfo.defence + csvInfo.defenceOffset * (level - 1)
mana = csvInfo.mana + csvInfo.manaOffset * (level - 1)
```

所以升级是“使用先天成长”的主要渠道，不是“提高先天成长”。

#### 飞升

`cortege_evolve_config.csv` 按品质和飞升等级给出潜能点：

| 飞升等级 | 潜能点增加 |
|---|---|
| 1 | 30 |
| 2 | 40 |
| 3 | 50 |
| 4 | 60 |
| 5 | 80 |
| 6 | 100 |
| 7 | 120 |
| 8 | 140 |
| 9 及以上 | 160 |
| 高等级 | 最高 400 |

`feishengUI.lua:383-395` 显示 `culturePointIncre`，即“潜能点增加”。

#### 转生

`cortege_reborn_layer.csv` 每层：

- `ret_culture = 150`
- `four_plus_rate = 2.5`

即转生层返还 150 潜能点，并带四项属性加成率字段。

> 注意：`four_plus_rate` 是服务端字段，客户端 `roleRebornUI.lua` 不参与换算，APK 内无法确认它最终作用于“当前四维”还是“成长率”。因此不能仅凭字段名断定它会改变先天成长值。

### 3. 飞升——潜能点 + 固定属性，不改变先天成长

相关文件：

- `ui/feishengUI.lua`
- `csv_config/cortege_evolution.csv`
- `csv_config/cortege_evolve_config.csv`

飞升消耗同英雄魂魄：

- 1 飞升：30 魂
- 2 飞升：45 魂
- 3 飞升：60 魂
- …
- 497～499 飞升：1200 魂

飞升收益：

1. 按 `cortege_evolve_config.csv` 增加潜能点。
2. 每级增加固定属性：

`feishengUI.lua:576-736`：

```lua
hp      = floor(csvInfo.hpOffset * 3) * evolve_level
damage  = floor(csvInfo.damageOffset * 3) * evolve_level
defence = floor(csvInfo.defenceOffset * 3) * evolve_level
mana    = floor(csvInfo.manaOffset * 3) * evolve_level
```

即：**飞升每级给四项属性各增加“基础成长 × 3”的固定值**。
这会让当前属性大幅增加，但详情页四条成长值仍不变。

飞升还有“化凡”回退：

- `cortege_devolve.csv` / `String.plist: devolve2/3`
- 化凡把飞升等级置 0，返还相应类型五星界魂，并按培养情况比例扣除已培养的飞升潜能点。
- 这是回退/返还，不是净增渠道。

### 4. 转生——潜能点 + 转生属性 + 仙脉

相关文件：

- `csv_config/cortege_reborn_layer.csv`
- `csv_config/cortege_reborn_effect.csv`
- `csv_config/cortege_reborn_vein.csv`
- `csv_config/cortege_reborn_config.csv`
- `lua/ui/roleRebornUI.lua`

#### 神仙转生

25 位神仙有转生形态，例如：

- 孙悟空 → 齐天大圣
- 猪八戒 → 天蓬元帅

- 如来 → 现世佛

转生层 1～9：

| 层 | 最低等级 | 重置等级 | 返还潜能点 | 四维加成率 | 材料 |
|---|---|---|---|---|---|
| 1 | 165 | 155 | 150 | 2.5 | 伏心转生石 20 + 轮回舍利 10 |
| 2 | 170 | 160 | 150 | 2.5 | 伏心转生石 30 + 轮回舍利 15 |
| 3 | 175 | 160 | 150 | 2.5 | 伏心转生石 40 + 轮回舍利 20 |
| 4 | 175 | 160 | 150 | 2.5 | 明心转生石 20 + 轮回舍利 20 |
| 5 | 185 | 170 | 150 | 2.5 | 明心转生石 30 + 轮回舍利 30 |
| 6 | 185 | 170 | 150 | 2.5 | 明心转生石 40 + 轮回舍利 40 |
| 7 | 195 | 180 | 150 | 2.5 | 无上转生石 20 + 轮回舍利 40 |

材料来源：

- 轮回舍利 1329、伏心转生石 1330、明心转生石 1331、无上转生石 1332
- `item_name.csv` 的 `product_desc`：九幽玩法产出

转生属性效果 `cortege_reborn_effect.csv`：

- 平衡型：每层给攻/防/血/法四项固定值
  - 1 层：攻 +300、防 +200、血 +800、法 +150
  - 9 层：攻 +600、防 +500、血 +1300、法 +300
- 攻血型：按层交替给攻击或生命
- 防血型：按层交替给防御或生命

转生后的“仙脉”系统 `cortege_reborn_vein.csv`：

- 9 层 × 9 脉，共 81 个节点
- 消耗精魄石 10000 和指定精魄道具
- 给攻/防/血/法固定属性
- 属于转生后的独立属性树，不是先天成长

#### 角色转生

`roleRebornUI.lua` 是角色/主角转生界面：

- 条件：角色等级、历史最高转生次数、消耗材料
- 权益包含 `max_cortege_layer` 等
- 服务端消息：`msg_reborn_event`，`reborn_type.role`

它更偏向角色整体转生与神仙转生层数解锁，不等同于单个神仙的四条成长值。

### 5. 传承——转移等级与培养进度，不是净增

相关文件：`ui/inheritUI.lua`

- 消耗 **人参果 1002**，至少 1 个。
- 将源神仙的等级/经验转移给目标神仙。
- 源神仙等级重置为 1。
- 返还蟠桃：

`inheritUI.lua:1342-1351`：

```lua
local totle = hp_plus + gongji_plus + fangyu_plus + magic_plus
local ret = math.floor(totle / 5 * 10 * 0.5)
```

即按已培养总值返还培养材料。

`String2.plist`：

- `inheritPeachHint = 提示：转移神仙经验值，同时返还一定量消耗过的蟠桃`
- `inherit_giveback = 回馈蟠桃`

因此传承是“把等级/培养进度换到另一个神仙”，不是增加总成长。

---

### 6. 装备、法术、仙缘、助阵——只加当前属性

这些系统不会改写英雄四条基础成长：

- 装备：`equipmentUpgradeUI.lua` 使用 `base_*_plus + (level-1) * effect_plus` 计算装备属性。
- 法术：提供固定属性或百分比被动。
- 仙缘：`fate_config.csv` 按百分比增加当前属性。
- 助阵：`cortege_cheer_config.csv` 按助阵神仙属性比例传递。

它们都属于“当前四维”渠道，不是“基础成长系数”渠道。

## 三、渠道总表

| 渠道 | 主要消耗/条件 | 增加对象 | 是否改变详情页四条基础成长 |
|---|---|---|---|
| 升级 | 经验 | 当前四维按基础成长增加；服务端潜能点 | 否 |
| 培养 | 蟠桃、元宝、潜能点 | `hp_plus/gongji_plus/fangyu_plus/magic_plus` + 当前属性 | 否 |
| 飞升 | 同英雄魂魄 | 潜能点 + 每级“基础成长×3”固定属性 | 否 |
| 神仙转生 | 等级 165+、轮回舍利、转生石 | 返还 150 潜能点、四维加成率、转生固定属性 | 否（除非服务端把 `four_plus_rate` 解释为成长率，APK 无法证实） |
| 仙脉 | 精魄石、精魄 | 攻/防/血/法固定属性 | 否 |
| 传承 | 人参果 | 等级/经验转移；返还蟠桃 | 否 |
| 化凡 | 飞升等级 | 返还五星界魂；扣除部分飞升潜能点 | 否 |
| 装备/法术/仙缘/助阵 | 装备、法术、阵容 | 当前属性固定值/百分比 | 否 |
| 图鉴/详情 | 无 | 仅按全角色最大值归一展示 | 否 |

## 四、关键边界

1. **详情页“成长潜力”四条是固定模板值。**  
   原版没有“提升成长潜力”的独立养成系统；玩家看到的变化来自不同英雄模板，而不是把某个英雄的四条成长练高。

2. **真正可练的是“培养值/潜能点/当前属性”。**  
   培养加 `*_plus`，飞升加潜能点和固定属性，转生加潜能点、转生属性和仙脉，升级用基础成长放大当前属性。

3. **升级潜能点、培养随机率、保护字段、转生 `four_plus_rate` 的最终公式在服务端。**  
   APK 只包含客户端展示与配置表，无法还原服务端的每级潜能点数值、培养概率和 `four_plus_rate` 的最终作用对象，因此不能进一步编造精确公式。

4. **当前本地版只做了成长潜力展示。**  
   本地版尚未接入培养、飞升、转生、仙脉、传承等完整养成链；等级公式已按原版 `inheritUI/expbookUI` 的 `基础属性 + 基础成长 × (等级−1)` 重建（原版 `csvInfo.hp + csvInfo.hpOffset * (level - 1)`），不再使用早期本地简化规则 `基础属性 × (1 + 0.14 × (等级−1))`。等级经验表 `cortege_experience.csv` 与经验条展示的逆向说明见 `cloud_android/local_game/LEVEL.md`。
