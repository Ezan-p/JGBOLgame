# 主角修为机制逆向与应用

主角修为决定行者等级，与神仙经验分别结算。原包完整保留了 1 至 99 级、每级 8 个字段的配置，本次逐项应用原始整数。原客户端把实际奖励和当前等级交给服务端下发，因此能够严格还原配置数值及客户端展示，不能仅凭 APK 证明原服所有模式和活动的结算公式。

## 原版数值含义

| 字段 | 含义及应用边界 |
|---|---|
| `level` | 当前等级，表中为 1 至 99 |
| `upgrade_exp` | 当前级升下一级的修为门槛；采用逐级门槛，不把它当从 1 级起累计总量 |
| `win_exp` | 普通胜利修为配置 |
| `lose_exp` | 普通失败修为配置 |
| `cortege_exp` | 神仙经验相关配置，不叠加到主角修为；其与关卡经验的服务端组合不明 |
| `cortege_count` | 原版上阵数量配置，完整保留；本次不改动既有本地阵容系统 |
| `energy_win_exp` | 精力胜利修为配置；区别于体力战斗，原 `mainUI` 的加载函数只读取前六列 |
| `energy_lose_exp` | 精力失败修为配置 |

原表 1 级：升级 40，普通胜 5、负 2，精力胜 2、负 1；2 级：升级 110，普通胜 10、负 5，精力胜 5、负 2；99 级：升级 22453200，普通胜 495、负 247，精力胜 247、负 123。完整数据见逐级表，运行时直接读取原表，不用拟合曲线替换。

## 升级与修为进度

本地累计修为 `experience` 等于所有已跨越等级的门槛之和，加上当前级修为。当前级修为达到门槛时扣除该级门槛并进入下一级；一次获得大量修为可连续升级，余数保留。原客户端采用服务端当前等级、当前修为、下级门槛；累计字段是本地存档表示方式。

例如累计 39 为 1 级 39/40。按战前 1 级发胜利修为 5 后，累计为 44，显示 2 级 4/110。到达 3 级需累计 150，到达 4 级需累计 270，到达 99 级需累计 226271000。

99 级仍有非零门槛，因此“表止于 99”不能证明原服永久满级规则。本地在配置末级停止推进等级，保留超额修为，进度条显示最多 100%；不虚构 100 级门槛，也不擅自清零修为。这是缺少后续配置时的本地兼容策略。

## 奖励结算的确定部分与本地选择

原版确定的是上述表值、奖励字段和展示路径。战斗实际 `role_exp` 由服务端产生，客户端没有给出完整公式。以下属于明确采用的本地结算策略，不能据此宣称原服逐场收益完全一致。

1. 旅途按战前等级读取普通胜负列，平局按失败列。修为不随关卡神仙经验、首次三星或首通奖励翻倍。
2. 精英挑战、竞技切磋、仙盟试炼、剧情演武目前均扣除同一个本地体力池，因此统一读取普通胜负列，取消此前胜利固定 50、失败固定 0。本地存档的 `energy` 命名指体力池，并不等于原协议的精力。尤其本地镜像竞技不能当作原版竞技结算。
3. 独立实现精力奖励列的查值入口，逐级测试原值；当前模式没有原版独立精力池，不仅凭模式名称强行切换精力奖励。
4. 当前不添加未经确认的体力消耗倍数、VIP 倍率、活动倍率或经验加成。扫荡和活动奖励入口的字段已记录，未实现的玩法不凭空发奖。
5. 主角修为与神仙经验分别保存；经验书不增加行者修为。主角升级后，既有神仙经验模块按新主角等级计算等级限制。

若要求原服完整逐场一致，仍需要服务端结算代码或可验证的原服战斗、扫荡、加成与满级响应样本。现有 APK 不足以消除这些差异。

## 代码应用与存档

[role_progression.py](../安卓模拟器游戏台源码_2026-10-20/cloud_android/local_game/role_progression.py) 集中处理原表加载、门槛计算、旧档迁移与普通或精力奖励。旅途和其他战斗模式共用 `award_battle`，确保在奖励发放前取等级。首页沿用当前级修为与门槛展示；战斗结果统一显示“修为”，神仙经验继续单独列出。

旧档没有 `role_exp_schema` 时保留已有迁移策略：按旧 `1 + experience // 200` 取得等级，限制到本地可用的 99 级，再按旧级内进度占比映射到原表门槛，向下取整。迁移保存旧累计值、旧等级和转换后的累计值，并且只执行一次。这是本地存档兼容操作，不是原版游戏赠送修为。已有原表档案不重复转换。

## 复现与验证

在 `cloud_android` 目录执行：

```sh
.runtime/venv/bin/python scripts/export_role_progression.py
.runtime/venv/bin/python -m unittest discover -s tests -p 'test_role_progression.py'
```

专项测试逐行比较 99 级全部字段，覆盖每一级门槛两侧、普通与精力胜负四列共 396 种奖励、跨级余数、99 级超额保留、旧档幂等迁移，以及四种本地战斗模式的胜负实际结算。其他已有测试继续验证旅途结算、经验书与修为分离和请求幂等。

2026-10-23 验证结果：153 项测试全部通过（146 项在沙箱内通过，7 项本地端口测试在解除端口限制后通过）。APK 构建、签名校验、覆盖安装与启动成功，后端已重启且健康检查通过。更新前数据库已备份；登录后仅体力由 59 正常恢复到 60 及时间戳更新，修为、等级和资产保持不变。验证记录见 `outputs/role-progression-20261023/validation.json`。
