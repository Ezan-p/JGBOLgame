一、逆向结论：原版神仙经验的获取方式
原版神仙经验（客户端可见部分）共有 4 类来源，其中「经验书」与「战斗/扫荡」是主渠道：

来源	触发入口	经验值来源	关键证据
经验书·仙佛密卷	包裹使用 → 选择神仙 → 吃书	item_base.experience_plus（1041–1080，1200～1.56亿）	packageUI.lua:2069、expbookUI.lua:294-335、msg_def.lua:286/811
经验书·培元丹	同上	item_base.experience_plus（1401–1430，557万～6531万）	同上
战斗胜利（关卡/精英/演武）	战斗结算	服务端下发 rewards.cor_exp[i]（每个出战神仙一份）	fightUI.lua:2211-2217、2825-2832
扫荡	扫荡结算	服务端下发 exp_list[i]	saodangUI.lua:724、749
活动/祝福（附加）	雪人活动、感谢神	plus_cortege_exp、bless_value	snowmanUI.lua:1649-1650、godBlessUI.lua:1506-1545
注意：tollgate_config.csv 的 exp 列经 v2/String2.plist 的 gainExp2=神仙经验 确认，是神仙经验，不是主角修为；主角修为是 role_level_config.csv 的 win_exp/lose_exp，对应 str_xiuwei=修为。

二、详细规则（可确认部分）
1. 经验表 cortege_experience.csv
列：quality, level, experience；5 档品质 × 1～600 级，共 3000 行。
experience = 从该级升到下一级所需经验，即 next_exp。
1★～4★：1 级 120、2 级 250；5★：1 级 132、2 级 275。
ui/data.lua:758-776 读入 g_characterExpTable[quality][level]。
升级时 next_exp 取新等级的 g_characterExpTable[quality][new_level]（expbookUI.lua:1469-1479）。
2. 经验书使用流程（协议 1059）
packageUI.lua:2069：物品 base_experience_plus > 0 → 打开 expbookUI。
expbookUI.lua:294-335：把背包里所有 base_experience_plus > 0 的物品逐个数入列表，exp = base_experience_plus。
createSkillMutilSelectLayer：只允许选择 等级 < floor(主角等级 × 3) 的神仙。
sendEatExpbookRequest：发送 msg_consume_fairy_roll (1059)，字段为 cortege_id + roll_list[{type_id,count}]。
服务端结算后回调 onGetExpResult，刷新神仙面板。
物品分类：sub_type=99（仙佛密卷）、sub_type=100（培元丹）是神仙经验书；sub_type=101（药灵丹）描述为“提升炼药等级”，应排除。

3. 主角等级限制神仙等级（经验书结算规则）
expbookUI.lua:67-80：


lvLimit = {
  { lv = 0,   rate = 1   },   -- 低于 floor(主角等级*2.5)：100% 收益
  { lv = 2.5, rate = 0.2 },   -- floor(主角*2.5) ~ floor(主角*3)：20% 收益
  { lv = 3,   rate = 0   },   -- >= floor(主角*3)：0 收益（硬上限）
}
getExpResult（expbookUI.lua:939-985）：

need_exp = (cortege_experience[quality][level] - cur_exp) / rate
经验足够则升级、cur_exp = 0、剩余经验继续滚动（经验不丢失）
达到 floor(主角等级*3) 或品质 600 级时停止
menuEatExpbook 若 实际获得 < 投入 会弹出二次确认（防止浪费）
4. 战斗/扫荡结算
fightUI.lua：

reward_info.play_exp = rewards.role_exp → 显示“修为 +N”（主角经验）
reward_info.cor_exp = rewards.cor_exp[1]；2825-2832 按每个出战神仙显示“经验: +N”
2861：若 last_fight_level < level 且 cor_exp > 0，播升级动画
2915-2954：神仙经验条按 cur_exp / next_exp 显示
关卡基础经验：getLastFightExpAndMoney() 返回 tollgate_config.exp，在 fightUI.lua:2242 记为 cor_exp_old
role_level_config.csv（99 级）：


level, upgrade_exp, win_exp, lose_exp, cortege_exp, cortege_count, energy_win_exp, energy_lose_exp
1,     40,          5,       2,        70,           2,            2,              1

upgrade_exp：主角升下一级所需修为
win_exp/lose_exp：战斗胜负的主角修为
cortege_exp：疑似该主角等级下的单场神仙经验基准（客户端只加载、不计算，服务端使用）
cortege_count：可上阵神仙数
5. 属性公式（与等级联动）
inheritUI.lua / expbookUI.setCharacterPropertis：


生命 = 基础生命 + 生命成长 × (等级 - 1)
攻击 = 基础攻击 + 攻击成长 × (等级 - 1)
...
6. 无法从 APK 唯一还原的部分
战斗 rewards.cor_exp[] 与 rewards.role_exp 的服务端具体公式（客户端只显示）。
role_level_config.cortege_exp 是否就是单场神仙经验基准、如何与关卡 exp 叠加。
活动加成（雪人/祝福）的完整结算规则。
三、建议的本地实现方式
阶段 1：数据层（只读配置）
local_game/assets.py：
保留已加入的 exp_table。
新增 stage_exp：用原版 tollgate_config.csv 的 exp 替换当前合成的 30 + number*10。
新增 role_levels：读 role_level_config.csv（upgrade_exp/win_exp/lose_exp/cortege_exp/cortege_count）。
新增 exp_books：从 item_base.csv 取 experience_plus > 0 且 sub_type ∈ {99,100}，输出 {id, exp, show_level, name}。
阶段 2：规则层（新增 local_game/leveling.py）
next_exp(catalog, quality, level)：查 exp_table（兼容 int/str 键）。
limits(role_level, quality) → (normal=floor(role*2.5), max=min(floor(role*3), 600))。
apply_exp(catalog, quality, level, cur_exp, amount, role_level)：
严格实现 rate 1 / 0.2 / 0、逐级进位、经验不丢失；
返回 (new_level, new_cur_exp, levels_gained)。
can_use_book(role_level, level)：level < max。
阶段 3：服务层（local_game/service.py）
恢复 state["hero_exp"] = {ident: cur_exp}（仅数据存储，旧档自动补空）。
hero()：cur_exp 从存档读取，next_exp 由经验表计算（已有）。
battle()：
神仙经验：胜利后对每个出战神仙调用 apply_exp(..., stage.exp, role_level)。
主角修为：改用 role_level_config.win_exp（失败用 lose_exp），不再把 stage.exp 当修为。
升级后 training.ensure 已按等级差补潜能点，无需额外处理。
新增 op：use_exp_book {hero, items:[{key,count}]}：
校验拥有/数量、扣物品、累加 experience_plus、apply_exp、返回“神仙经验 +N / 升级”提示。
保留银两 upgrade 作为离线便利入口（或按确认结果移除）。
阶段 4：UI
经验条已显示 cur_exp/next_exp（上一轮已完成），经验增长后会自动填充。
战斗结算页：新增每个神仙“经验 +N”、主角“修为 +N”（对齐 fightUI.lua）。
经验书入口：inventory.lua 使用物品时，若 experience_plus > 0 则打开“选择神仙 + 选择经验书”面板（或先只做后端 op + 简单确认框）。
升级动画（可选）：对齐 fightUI.lua:2861 的升级提示。
阶段 5：主角等级（可选）
把当前本地 1 + 累计经验 // 200 替换为 role_level_config.upgrade_exp 逐级扣减，和原版一致。
四、需要你确认的实现范围
原版战斗 cor_exp 的服务端公式不可见，因此本地需要选一个明确口径（例如“每个出战神仙获得该关 exp”）。另外经验书 UI 与主角等级表是否本轮一起做，也需要确认。
